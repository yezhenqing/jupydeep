.. _installation:

Installation
============

Installation
------------

JupyDeep is available on PyPI and can be installed via pip (including within uv or conda environments). 

``uv`` installation
~~~~~~~~~~~~~~~~~~~

Using ``uv`` as an example, we can set up a project in a new directory named ``tutorial``. 

Ensure you have ``uv`` is installed. If not, please refer to the `uv installation guide <https://docs.astral.sh/uv/getting-started/installation/>`_.

.. code-block:: console

   $ cd tutorial
   $ uv init
   $ uv add jupyterlab jupydeep "jupyter-mcp-server @ git+https://github.com/yezhenqing/jupyter-mcp-server.git"


Then simply launch JupyterLab as below:

.. code-block:: console

   $ uv run jupyter lab --ip=0.0.0.0

The JupyterLab main panel should now display the JupyDeep icon in the right sidebar.


``conda`` installation
~~~~~~~~~~~~~~~~~~~~~~

For ``conda``, you can create a new environment and then install JupyDeep using ``pip`` inside it.

.. code-block:: console

   $ conda create -n jupydeep jupyterlab
   $ conda activate jupydeep
   $ (jupydeep) pip install "jupyter-mcp-server @ git+https://github.com/yezhenqing/jupyter-mcp-server.git" jupydeep


.. note::

   The original ``jupyter-mcp-server`` rely on ``jupyter-server-nbmodel``, which suffers from several known issues. 
   In particular, `Issue #65 <https://github.com/datalayer/jupyter-server-nbmodel/issues/65>`_ prevents notebooks from executing smoothly.

In both ``uv`` and ``conda``, you can install any additional packages you need (such as ``seaborn`` for data analysis).


.. tip::

   **Troubleshooting: Terminating Unresponsive Jupyter Processes**

   Occasionally, the JupyterLab or JupyDeep process may become unresponsive and cannot be gracefully terminated using ``Ctrl + C``. 
   If this occurs, you can forcefully terminate the active server instance from another terminal console by running:

   .. code-block:: console

      $ pkill -9 jupyter


.. warning::

   **Notice: Setting Schema Incompatibility**

   If you have a previous installation of JupyDeep, newer versions may introduce breaking changes to the setting JSON schemas that are incompatible with your existing configuration. Please inspect your local Jupyter user settings file. 

   You can locate your specific Jupyter configuration and user settings directories by running:

   .. code-block:: console

      $ uv run jupyter --paths

   Typically on Linux, user settings for JupyDeep reside under the Jupyter config directory. You can list them via:

   .. code-block:: console

      $ ls ~/.jupyter/lab/user-settings/jupydeep/ -l

   Inside this directory, you should find the following core JSON configuration files:

   * ``agent.jupyterlab-settings`` – Agent-specific behavior and capability options
   * ``global.jupyterlab-settings`` – Global server connectivity and tracking settings
   * ``llm.jupyterlab-settings`` – LLM provider and model parameters
   * ``mcp.jupyterlab-settings`` – Model Context Protocol server configurations
   * ``skill.jupyterlab-settings`` – Custom agent skill paths and definitions

   **For simplicity, you can delete these json files (if they exist) prior to reinstalling JupyDeep. 
   After installation, you will need to reconfigure them.**

   If you prefer to manually update these settings, please refer to the detailed 
   ** `JSON schemas <https://github.com/yezhenqing/jupydeep/tree/main/schema>`_ ** in our GitHub repository 
   to ensure your local configurations remain compatible with the latest schema definitions.
